- **`EVIDENCE_MIN_SCORE`를 0.75로 정한다.** `evaluate.py --min-score 0`으로 46문장을 실제 실행해 보니 기대한 자료의 최고 점수는 0.762~0.887, 함께 붙는 무관한 두 번째 근거는 0.728~0.811이었다. 0.75는 맞는 근거를 모두 남기고 0.73대 잡음을 거른다. 정답 최저점과의 여유가 0.012뿐이라 자료를 바꾸면 다시 보정한다.

## 2026-11-12 · 문법 자료 보강 (Claude Code)

- **문법 자료를 59건에서 70건으로 늘린다.** 초·중급 교재에서 자주 다루는데 빠져 있던 부터/까지·에서/까지, (이)나, 처럼/같이/마다, -(으)면서, -기 전에/-(으)ㄴ 후에, -지요/-네요/-군요, -던, -기로 하다, -(으)ㄹ 줄 알다, -(으)ㄴ 지, -대요/-데요를 넣었다. 형식과 범주 체계는 그대로다.
- **을/를·이/가·은/는에 받침 형태 오류 사례를 넣는다.** 배포본에서 '영화이 봤어요'에 '에: 시간' 자료가 붙은 일이 있었는데, 받침에 따른 형태를 틀린 사례가 자료에 없었다.
- **평가 문장 7개를 추가한다**(새 항목 6개 + '영화이 봤어요'). 실제 실행에서 7개 모두 기대한 자료를 찾았다.

## 2026-11-12 · 검색 질문 재평가 (Claude Code)

- **검색 질문을 "표현 + 바로 뒤 어절 + 그 문장"으로 만든다.** `a76d987`에 들어간 "표현 + 뒤 어절"만 쓰는 방식은 실제 평가에서 검색 적중이 0.929로 이전 방식(문장 전체, 1.0)보다 낮았다. '할머니와 … 자요'(높임), '제 취미는 … 읽어요'(문장 짜임), '안녕하세요. 나는 학생이야'(말 단계)처럼 판단 단서가 표현 앞에 있는 경우를 놓쳤다. 두 실행의 모델 분석 결과 49건을 고정하고 검색만 다시 돌리면 문장 전체 47건, 표현+뒤 어절 44건, 둘을 합친 방식 48건에서 맞는 자료가 상위 2개 안에 들었다.
- '영화이 봤어요'는 세 방식 모두 p-object가 1위였다. 배포본에서 '에: 시간'이 붙은 일은 자료 보강(받침 형태 오류 사례) 전의 일이고, 질문 방식만의 문제는 아니었다.
- **같은 평가에서 탐지 재현율·범주 정확도는 질문 방식과 무관하다.** 분석(03단계)은 검색 전에 끝난다. 네 실행에서 재현율 0.833~0.875, 범주 정확도 0.707~0.825로 흔들린 것은 모델 실행마다의 차이다.
- **`EVIDENCE_MIN_SCORE`를 0.74에서 0.73으로 낮춘다.** 질문이 길어지며 점수가 조금 내려가 맞는 근거 중 0.731(x04 h-special, 2순위)과 0.733(m01 1순위)이 0.74 아래로 떨어졌다. 무관한 근거는 0.73~0.74 사이에 1건(0.738)이었다. 맞는 근거와 무관한 근거의 점수가 겹쳐 기준 하나로 깨끗이 나눌 수 없다. 기준은 근거가 아예 없는 것을 막는 하한으로 쓰고, 상위 2개 안의 무관한 근거는 모델이 인용하지 않는 것에 기댄다(화면은 인용한 근거만 보여 준다, `web/app.js`).
